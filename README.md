# 유림에퐁당 · 통합현황 대시보드

정적 파일 2개(`index.html`, `app.js`)로만 이루어진 순수 프론트엔드입니다.
빌드 과정이 필요 없어서 GitHub Pages에 그대로 올리면 바로 동작합니다.

## GitHub Pages로 배포하기

1. 새 저장소를 만들고 `index.html`, `app.js` 를 루트에 올립니다.
2. 저장소 **Settings → Pages** 에서 Source를 `main` 브랜치 / `root` 로 설정합니다.
3. 몇 분 뒤 `https://<계정명>.github.io/<저장소명>/` 으로 접속하면 됩니다.

기존 `유림에퐁당` 사이트(Railway) 안에 페이지 하나로 넣고 싶다면, 이 두 파일을
정적 파일 서빙 경로(`/public`, `/static` 등)에 넣고 라우팅만 연결하면 됩니다.

## 지금 상태 (중요)

- **데이터는 지금 이 브라우저의 localStorage에만 저장돼요.** 즉, 내가 입력한 값은
  내 컴퓨터/브라우저에서만 보이고, 다른 사람 화면이나 다른 기기에는 반영되지 않아요.
  지점 담당자가 각자 입력하고 본사가 한 화면에서 모아보는 "진짜 통합"이 되려면
  데이터를 **서버(데이터베이스)에 저장**하도록 바꿔야 해요.
- 매장 목록은 이제 **화면에서 직접 추가·삭제·수정**할 수 있어요 ("가맹점 정보 관리" 메뉴 →
  "+ 새 지점 추가" 버튼 / 각 행의 "삭제" 버튼 / 모든 항목 입력칸). 맨 처음 한 번만 `app.js`
  상단 `RAW_STORES` 배열(예시 데이터)로 초기화되고, 그 뒤로는 화면에서 고친 내용이 브라우저에
  계속 저장돼요. 초기 매출 수치도 예시로 채워져 있으니 실제 값으로 입력해주세요 — 전월매출은
  "마감장표 업로드"를 쓰면 자동으로 채워져요(아래 참고).

## 다음 단계로 서버에 연결하려면

`app.js`에서 아래 두 함수만 API 호출로 바꾸면 됩니다. 나머지 화면 로직은 그대로 써도 됩니다.

```js
// 지금: localStorage에서 읽기
function loadSales(){ ... }

// 나중: 서버에서 읽기
async function loadSales(){
  const res = await fetch('/api/sales');
  return res.json();
}
```

```js
// 지금: localStorage에 쓰기
function saveSales(data){ localStorage.setItem(...) }

// 나중: 서버에 쓰기
async function saveSales(data){
  await fetch('/api/sales', { method:'POST', body: JSON.stringify(data) });
}
```

기존 유림에퐁당 사이트에 이미 로그인·DB가 있다면, 그 API에 맞춰 이 두 함수만
고치면 이 화면 그대로 실제 서비스에 붙일 수 있어요.

## 화면 구성

- **매출장표** — 전 지점 순위표 (당월누적/전일/토요일, 브랜드 필터)
- **공지용 마감장표** — 브랜드별 마감 현황표를 가맹점 공지 양식 그대로 자동 생성 (순위/지역/지점명/사업개시일 + 당월매출현황 + 전월·전년동월 대비 + 로열티현황). 우측 상단 "인쇄/PDF로 저장" 버튼으로 바로 출력 가능
- **매출성과분석표** — 브랜드별 매출 비중, 전월·전년동월 대비 (Chart.js)
- **매장별현황** — 지점 카드 + 클릭 시 상세(임대료·로열티·평당매출 등)
- **매출 데이터 입력** — 포스(OK포스/업솔루션-퐁당/업솔루션-얼얼하이/유니온포스/유플러스포스)별 탭으로 나뉘어 있고, 실제 포스 화면과 같은 컬럼 구성. 포스 관리자 화면에서 표를 복사해 셀 하나만 클릭하고 붙여넣으면 여러 지점·여러 컬럼이 한 번에 채워져요. 지점명으로 자동 매칭되니 순서가 달라도 상관없어요.
- **가맹점 정보 관리** — 지점 추가·삭제와 브랜드·매장명·사용 포스·지역·가맹점/직영점·대표자명·사업자번호·소재지 주소·로열티(정률/정액)·사업개시일·평수·임대료 등 모든 항목을 등록/수정. 저장하면 매출 데이터 입력을 포함한 다른 모든 화면에 바로 반영되고, 매장명·브랜드를 바꿔도 이미 입력한 매출 데이터는 새 이름으로 함께 옮겨져요.
- **마감장표 업로드** — 매월 마감 완료된 엑셀 파일을 월별로 올려두는 보관함. 파일 안에서 지역·지점명·당월누적매출 등 컬럼을 자동으로 인식해서, 공지용 마감장표와 **완전히 같은 화면 양식**으로 다시 보여줘요. 공지용 마감장표의 "조회 월"에서 해당 월을 고르면 실시간 데이터 대신 업로드해둔 그 달의 수치가 나와요. 가장 최근에 올린 달의 당월누적매출은 실시간 화면의 "전월매출"에도 자동 반영돼요 (예: 6월분을 올리면 7월 실시간 화면의 전월매출이 자동으로 6월 수치가 됨).

## 메뉴 구성

왼쪽 메뉴는 "통합현황"/"운영" 두 카테고리로 나뉘어 있고, ⠿ 아이콘을 잡고 드래그하면 같은 카테고리 안에서든 다른 카테고리로든 원하는 위치로 옮길 수 있어요. 순서는 브라우저에 저장돼서 다음에 열어도 그대로예요.

## 모바일

860px 이하 화면에서는 왼쪽 메뉴가 화면 하단 탭바로 바뀌어요. PC 레이아웃은 그대로 유지됩니다.

## 인쇄

공지용 마감장표 화면에서 "인쇄 / PDF로 저장"을 누르면, 인쇄용으로 글씨 크기와 줄바꿈을 자동으로 조정해서 겹침 없이 출력돼요 (화면에 보이는 것과는 별도로 인쇄 시에만 적용).

## 지점 정보·포스 매핑 바꾸기

이제 코드를 고칠 필요 없이 **"가맹점 정보 관리" 화면**에서 다 됩니다 — 지점 추가/삭제,
브랜드·매장명·사용 포스 변경까지 화면에서 처리하면 매출 데이터 입력을 포함한 모든 화면에
자동으로 반영돼요.

(`app.js` 상단 `RAW_STORES` 배열은 브라우저에 저장된 지점 데이터가 하나도 없는 **최초
한 번**에만 쓰이는 초기 예시값이에요. 이미 한 번이라도 열어본 브라우저에서는 이 배열을
고쳐도 반영되지 않으니, 배포 자체를 새로 시작하는 게 아니라면 가맹점 정보 관리 화면을
쓰세요.)

## 마감장표 업로드 파일 형식

업로드하는 엑셀 시트 안에 아래 헤더가 한 줄에 들어있어야 자동으로 인식돼요 (열 순서는 상관없어요):
`지역, 지점명, 사업개시일, 전일매출, 영수건수, 영수단가, 당월누적매출(또는 당월누적), 당월예상마감(또는 예상마감), 일평균매출, 전월매출, 증감률, 전년동월매출, 증감률`

헤더 바로 위 1~3줄 안에 브랜드명(퐁당/유림대패/려원장어/얼얼하이)이 적혀 있어야 어느 브랜드인지 인식해요. 로열티현황은 `로열티율, 당월누적기준, 예상마감기준` 헤더로 인식돼요. 헤더 칸 안에 줄바꿈이나 공백이 섞여 있어도(예: "당월"과 "누적매출"이 줄바꿈으로 나뉜 경우) 자동으로 무시하고 인식해요.

브랜드명이 위 4개와 다르게 적혀 있는 파일(예: 얼얼하이 대신 "마라꼬치")은 `app.js`의 `BRAND_ALIASES`에 등록해두면 인식돼요 — 지금은 `마라꼬치 → 얼얼하이` 한 쌍이 등록돼 있어요.

## 커스터마이징 포인트

- 색상/폰트: `index.html` 상단 `<style>` 의 `:root` 변수
- 지점·브랜드(기존 브랜드 중 선택)·포스·로열티율/정액·평수·임대료 등 지점별 데이터: 코드가 아니라 **"가맹점 정보 관리" 화면**에서 관리 (최초 예시 데이터만 `app.js` 상단 `RAW_STORES`)
- 브랜드 종류 자체(퐁당/유림대패/려원장어/얼얼하이)를 늘리거나 이름을 바꾸는 건 아직 코드 수정이 필요해요 — `app.js`의 `BRANDS`, `BRAND_COLORS`, 그리고 `index.html`의 브랜드 필터 버튼들
